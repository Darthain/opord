# ARTIC AI v0.3.30.1 — Hardening Patch Plan

## Purpose

v0.3.30 is moving in the right direction, but before another long benchmark we should harden task ownership and lifecycle semantics so that the RPT tells us about genuine tactical/navigation problems rather than stale or contradictory state.

The v0.3.30.1 goal is **not** to add new tactics or rewrite navigation. It is to make plan/task ownership deterministic.

---

## 1. Centralise Section Task State

### New function
`functions/fsm/fn_setSectionTaskState.sqf`

This becomes the only legal way to change `ARTIC_sectionTaskState`.

### Allowed lifecycle

```text
ASSIGNED
   ↓
DEPLOYING
   ↓
READY
   ↓
EXECUTING
   ↓
COMPLETE

ASSIGNED / DEPLOYING / READY / EXECUTING
   ├── FAILED
   └── ABORTED
```

Terminal states:

```text
COMPLETE
FAILED
ABORTED
```

Once a task enters a terminal state, no later code may return it to READY or EXECUTING.

### Required validation

Every transition must match:

```text
current planId == supplied planId
current taskId == supplied taskId
```

If not, reject the transition and emit a debug line.

### Files changed

- `functions/fsm/fn_signalSectionReady.sqf`
- `functions/fsm/fn_signalSectionFailure.sqf`
- `functions/tactics/fn_finishPlan.sqf`
- tactical executors that currently write `ARTIC_sectionTaskState` directly
- `config.cpp` to register the new function

---

## 2. Make READY Signalling Identity-Safe

Current `fn_signalSectionReady.sqf` writes the state directly.

Change it so it:

1. captures `planId` and `taskId`;
2. calls `ARTIC_fnc_setSectionTaskState` with `READY`;
3. sends `ARTIC_sectionReady` only if the transition succeeded;
4. refuses READY from FAILED / ABORTED / COMPLETE tasks;
5. ignores READY generated by an obsolete task.

Expected telemetry:

```text
[ARTIC][Alpha 1-2] TASK STATE plan=B1_PL_P3 task=B1_PL_P3_SEC_2 DEPLOYING -> READY
```

Rejected transition example:

```text
[ARTIC][Alpha 1-2] TASK STATE REJECTED plan=B1_PL_P3 task=... FAILED -> READY
```

---

## 3. Make FAILURE a Terminal Task Transition

`fn_signalSectionFailure.sqf` should transition the matching task to `FAILED` before reporting upward.

Required behaviour:

```text
EXECUTING
   ↓
FAILED
   ↓
ARTIC_sectionFailed event
```

A duplicate failure report for the same task should be ignored or logged once without changing state again.

The failure event must carry:

```text
commanderId
formationId
sectionId
planId
taskId
role
reason
timestamp
```

---

## 4. Add Identity-Safe Task Abort

### New function
`functions/fsm/fn_abortSectionTask.sqf`

Arguments:

```sqf
[group, planId, taskId, reason]
```

It must only modify the section if the supplied identity still owns the section.

On success:

```text
task state -> ABORTED
ARTIC_planAbortId = planId
cancel owned play handle
clear H-hour latch for that task
clear tactical play variables owned by that task
```

It must not touch any newer task.

This function becomes the mechanism used during plan supersession.

---

## 5. Replace Generic Stale Cleanup with Identity-Safe Cleanup

### New function
`functions/tactics/fn_endPlayQuietly.sqf`

Purpose: terminate an obsolete tactical script without disturbing the replacement task.

Arguments:

```sqf
[group, planId, taskId]
```

It should only clear variables if they are still owned by that exact plan/task.

It must **not** blindly do what `fn_finishPlan.sqf` currently does, such as resetting the section destination, movement owner, tactical guide, or formation if a newer task is already active.

### Rule

```text
normal successful/current play end
    -> fn_finishPlan

stale/superseded play end
    -> fn_endPlayQuietly
```

Update:

- `fn_executePlatoonManoeuvre.sqf`
- `fn_executeFixingAction.sqf`
- `fn_executeBlockingAction.sqf`
- any helper that uses `ARTIC_fnc_isPlayStale`

---

## 6. Make Plan Supersession Abort Children First

Update `fn_supersedePlatoonPlan.sqf`.

Required order:

```text
PLATOON enters REASSESS
        ↓
mark P1 SUPERSEDED
        ↓
abort every active P1 section task
        ↓
wait until P1 child executors are settled
        ↓
create P2
        ↓
apply P2
```

Do not create/apply P2 while old P1 execution still owns a section.

Telemetry:

```text
FSM PLAN SUPERSEDED plan=P1
FSM TASK ABORT plan=P1 task=P1_SEC_1
FSM TASK ABORT plan=P1 task=P1_SEC_2
FSM TASK ABORT plan=P1 task=P1_SEC_3
FSM PLAN CHILDREN SETTLED plan=P1
FSM PLAN CREATED plan=P2
```

---

## 7. Fix Failure Settlement to Include Script Handles

Current platoon settlement only checks `ARTIC_currentPlan`.

Update `fn_platoonRuntimeCondition.sqf` so a section is considered to have an active play if either:

```text
ARTIC_currentPlan != ""
```

or:

```text
ARTIC_playHandle is still running
```

Recommended helper:

### New function
`functions/tactics/fn_isSectionPlayActive.sqf`

This should be the single definition used by both `groupStep` and the Platoon FSM.

A failure is settled only when:

```text
failure exists
AND
no matching currentPlan remains
AND
no matching playHandle remains alive
```

---

## 8. Make H-Hour Single-Consumption Per Task

Add section variables:

```text
ARTIC_hHourConsumedPlanId
ARTIC_hHourConsumedTaskId
```

Before a tactical executor begins its post-H-hour stage, it must atomically verify:

```text
current plan/task matches
task state == READY
H-hour plan matches
H-hour not already consumed for this task
```

Then:

```text
READY -> EXECUTING
```

and set the consumed IDs.

Duplicate H-hour delivery should log:

```text
H-HOUR DUPLICATE IGNORED plan=P4 task=P4_SEC_1
```

No second Stage 1 may start.

---

## 9. Fix HOLD Plan Semantics

`fn_tryIssuePlatoonHHour.sqf` currently requires `requiredReady` to be non-empty.

A HOLD plan can legitimately have zero required manoeuvre elements, so it should not sit forever in READY_CHECK.

Add a dedicated Platoon state:

```text
HOLD
```

or, for the smallest 3.30.1 change, handle HOLD as a special plan phase.

Recommended flow:

```text
scheme=HOLD
   ↓
plan status=HOLD
   ↓
sections occupy reserve/hold positions
   ↓
periodic battlefield reassessment
   ├── still no tactical option -> HOLD
   └── tactical opportunity     -> REASSESS / create new plan
```

No H-hour is issued for a pure HOLD plan.

Update:

- `fn_tryIssuePlatoonHHour.sqf`
- `fn_platoonRuntimeCondition.sqf`
- `fn_platoonRuntimeEnterState.sqf`
- CBA Platoon state-machine creation/config

---

## 10. Unify Play Ownership

Every tactical play must store:

```text
ARTIC_playPlanId
ARTIC_playTaskId
ARTIC_playHandle
ARTIC_playType
```

When a new play starts, `groupStep` must refuse to start another play while an owned handle is active.

This includes:

```text
PLATOON_MANOEUVRE
FIX
BLOCK
ASSIST/SUPPRESS
```

The existing `ARTIC_assistCall` / `ARTIC_fnc_suppressElement` path should join the same ownership system so an assist fire task cannot overlap a normal tactical play invisibly.

---

## 11. Preserve v0.3.30 Tactical Improvements

Do not remove or redesign in 3.30.1:

- contact-aware replanning;
- distance-scaled movement deadlines;
- progress-based READY_CHECK timeout;
- improved FIX behaviour;
- improved BLOCK behaviour;
- failure classes;
- current tactical schemes;
- existing route planner.

This build is ownership hardening only.

---

## 12. Deferred to v0.3.31+

Do not add yet:

```text
full navigation cost field
short navigation gates rewrite
actual PathCalculated navigation integration
new tactical schemes
full Fireteam FSM runtime
reliable suppression/fire-control redesign
```

These should be tested after ownership is clean.

# Test Sequence

## Test A — lifecycle unit test

Force one section task through:

```text
ASSIGNED -> DEPLOYING -> READY -> EXECUTING -> FAILED
```

Then attempt:

```text
FAILED -> READY
```

Expected: rejected.

---

## Test B — supersession test

Create P1, allow section plays to begin, force one tactical failure.

Expected:

```text
P1 failure
P1 superseded
all P1 tasks aborted
all P1 handles stopped
P2 created
```

There must be **zero P1 Stage1/Stage2/H-hour execution after P2 creation**.

---

## Test C — duplicate H-hour test

Deliver the same H-hour event twice.

Expected:

```text
first event -> READY -> EXECUTING
second event -> DUPLICATE IGNORED
```

Only one Stage 1 starts.

---

## Test D — HOLD test

Force planner to return HOLD with `requiredReady=[]`.

Expected:

```text
plan status=HOLD
no H-hour
no READY_CHECK deadlock
periodic reassessment continues
```

---

## Test E — normal Air Station benchmark

Use the unchanged benchmark mission.

Success criteria:

1. Roles remain stable inside one plan ID.
2. Terminal task state never reverses.
3. Superseded plan scripts stop before the next plan executes.
4. H-hour is consumed once per task.
5. HOLD does not deadlock.
6. No overlapping tactical play handles per section.
7. Any remaining bizarre movement can now be treated as a genuine navigation/planner problem.
